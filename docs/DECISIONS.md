# VANTA design decisions

These are proposed M0 decisions. The validation column identifies the evidence that can change them. [Architecture](ARCHITECTURE.md), [test strategy](TEST_STRATEGY.md).

| Decision | Rationale and trade-off | Validation |
| --- | --- | --- |
| **D01 Use the TrueForge TypeScript SDK behind a narrow adapter.** | The SDK supplies typed session, turn, SSE and approval contracts. One adapter limits version drift. Documented HTTP remains an escape route for a proven SDK defect, with extra serialization and reconnection work. A separate orchestration layer would duplicate TrueForge and fail the competition gate. | M2 checks the pinned `0.185.1` server with SDK `0.185.0`. M8 checks the organizer's `@latest` setup. |
| **D02 Use a VS Code extension-host MCP server over loopback Streamable HTTP.** | Co-locating the MCP server with VS Code gives tools access to unsaved buffers, language providers and run state. Loopback keeps the native Windows setup local. A separately launched stdio server would need an editor bridge and a compatible TrueForge launch path. Dynamic connector registration adds lifecycle and secret management. | M2 verifies registration, header propagation, loopback access and cleanup. M3 verifies run isolation, reinitialization and crash recovery. |
| **D03 Use native review plus a React Agent Studio.** | VS Code's diff editor supplies familiar comparison, keyboard and theme behavior, while React reduces complexity for coordinated timeline, context, review and history components. A plain DOM view would reduce bundle weight and is acceptable for a limited first Studio. Preserve native review as the most direct way to show the mandatory edit experience. | EXT-01 through EXT-03 and EDIT-01. Evaluate paint cadence and bundle size before expanding dependencies. |
| **D04 Use lexical retrieval with optional language-provider signals.** | Ripgrep and symbol providers give relevant, inspectable evidence without an index service or embedding costs. One-hop definition and import expansion captures obvious dependencies and keeps budgets stable. Dynamic imports and repositories with weak language tooling may rely on search. A vector index would add indexing time, another model and weaker explanations for the first delivery. | CTX-01 through CTX-03 on sparse symbols, large repos and no `rg`, then blind Task B. |
| **D05 Stage edits and let TrueForge pause for exact proposal review.** | A dedicated gated checkpoint presents complete hunks and preserves a real approval trace. If only some hunks are approved, the bridge receipt conveys the reduced overlay and the host can commit only that revision after success. Letting an approved MCP tool write to disk immediately would couple review to run completion and complicate cancellation. Revisions, user decisions and recovery add state to manage. | MCP-02 and EDIT-01 through EDIT-03, including approval outside VANTA, duplicate calls and partial saves. |
| **D06 Use guarded native text edits and an inverse journal.** | This keeps editor buffers and standard UX in sync and provides explicit recovery for mixed file operations and disk saves. A raw patch process would bypass open unsaved buffers. A VANTA journal cannot provide a filesystem-wide transaction across saves. Conflicts require guarded recovery and disclosure. | EDIT-02, EDIT-03 and REL-01 on Windows with formatters and external changes. |
| **D07 Use deferred loading for follow-up tools.** | This is visible, scored harness functionality and saves up-front tool schema budget without requiring a sandbox. Selective preload keeps essential edits and approvals easy to reach. Additional discovery calls can cost latency or fail with weak tool-calling models. Code Mode adds sandbox dependency and subagents add turn complexity. | TF-04 compares actual deferred/eager sessions. Decide which tool to defer from actual Task B tool usage, then show it in the video. |
| **D08 Execute only explicit command profiles on trusted snapshots.** | This meets the terminal tool requirement and can exercise tests against user-reviewed proposals with no TrueForge sandbox. A profile and argument schema reduce injection risk. Python test code still has developer privileges, so the snapshot alone is only a working-tree safety measure. Arbitrary shells and hidden WSL setup would increase risk and undermine clean Windows setup. | MCP-03 and SEC-03, including timed child cleanup and staged snapshot fidelity. |
| **D09 Treat fallback as a new TrueForge attempt.** | A fresh session lets the alternate model use its own configured provider while protecting against stale approvals, partial context and replay. A single proven failure classification and one alternate attempt limit duplicates and cost. Clear error and bounded transient retries are needed even with fallback. | REL-02 and REL-03 against a real provider-level failure. Use the achieved anchor in the scorecard. |
| **D10 Start from the existing MIT repo.** | Working from `e32712c` keeps the code small and the TrueForge loop easy to audit. An editor-side fork could accelerate polish if the team can preserve the exact fork point and attributions and remove upstream orchestration completely. | M8 verifies licenses, disclosure, setup and absence of provider bypasses and secrets. |

## Open assumptions

1. A genuine session on Windows can discover an authenticated extension-host MCP server and deliver the expected source call and native approval events. The pinned source establishes API shapes. The live contract run must establish actual behavior.
2. A compatible model can reliably search, use tools, stage multi-file changes and reach the review checkpoint under the configured budget. `gemini-3-5-flash-lite` responded in the team's prior setup. Multi-step tool reliability, quotas and a suitable second configured model are still to be measured.
3. The chosen VS Code version and filesystem preserve encodings and expected undo outcomes across dirty documents, saves and file creation. Verify initial support for ordinary UTF-8 text including BOM and CRLF, and report unsupported encodings before staging.
4. Cancellation, reconnection and deferred approval keep late or duplicate work inside the authenticated run and respect the terminal state under real transport failures. Measure full process cleanup on Windows and enforce the host cancellation boundary independently of the server.
5. Task B's proposed deferred capability is genuinely useful on the Flask checkout and identifiable in the session. Choose and document the final policy from captured traces.
6. The exact public release and model setup used for recording can be repeated from a fresh checkout within the November deadline. Verify `@latest` compatibility and use accurate limitations and timestamps in the submitted scorecard.
