# Agent Mode

Open a trusted single-folder workspace in VS Code. Start local TrueForge and configure the exact model registered there. Keep the outbound network policy enabled and allow `127.0.0.1` for VANTA's authenticated per-run MCP connector. Follow the [README setup](../README.md).

Set **VANTA: Verification Python** in User Settings to an absolute path to a trusted Python interpreter with pytest and the project's dependencies available. On Windows a dedicated virtual environment's `Scripts/python.exe` is suitable. Use the project's declared dependencies when preparing the environment. During rehearsal set **Files: Auto Save** to **off**.

1. Enable **Agent Mode** and **Share workspace context** in Agent Studio. Submit one request for changes to existing files.
2. Use Context Explorer to see discovery results and the paths and reasons that entered the model context. Review the proposed files in Agent Studio. Selecting a hunk opens or navigates its native VS Code diff. Accept or reject each hunk, then choose **Approve selected hunks**. Related changes may depend on one another.
3. Inspect the displayed pytest target. Choose **Allow once** to run that profile against a disposable snapshot with the accepted changes. Denying a gate, stopping before apply, a failed check or an incomplete TrueForge turn leaves the source buffers untouched.
4. After verification and successful turn completion, VANTA checks the targets again and applies the accepted changes in one VS Code text edit batch. If VS Code released a clean target buffer during review, VANTA reopens it and checks it against the staged source before applying. Use **File → Save All** to persist the accepted changes. The Changes panel offers **Undo Agent changes** while the affected buffers still match the applied batch. Save again if you want to persist a buffer undo after saving the batch.

## Definition and boundaries

The versioned definition is the `agentModeDefinition` factory in [src/trueforge.ts](../src/trueforge.ts). Enable Agent Mode in a clean extension build to instantiate it automatically with the configured model and a fresh authenticated connector. The factory contains the exact instructions, deferred discovery configuration, local tool allowlist, and required approval names. The approval-gated tools are `review_changes` and `run_verification`. Workspace discovery and `stage_file_edit` have no authority to edit source files. Each run uses a dedicated TrueForge session.

Agent Mode supports up to 12 existing, clean UTF-8 text files and 60 independently selectable hunks. A staging argument uses exact unique text anchors. Context has a whole-turn token budget and the bridge bounds reads and request size. Apply checks path scope, file content and editor version. If a batch is interrupted, VANTA attempts to restore buffers that still have the exact written content. Review any paths named in a recovery error in the editor. The in-memory undo is scoped to the current window and latest applied Agent Mode batch.

Agent Mode uses the same reasoning effort selection as [Quick Edit](QUICK_EDIT.md#capture-and-staging). It prefers high when the selected model advertises support in TrueForge.

When staging a Python insertion, VANTA checks whether a new top-level declaration splits an existing function or class. When both versions parse and the insertion splits a definition, the staging response gives the original boundary lines. The model can correct the rejected file in the same turn. The Python check parses source without importing it, and native review still checks the staged Python for syntax errors.

Set **VANTA: Verification Ruff** in User Settings to the absolute path of a trusted local Ruff executable to check Python edits for newly introduced undefined names. VANTA compares Ruff's `F821` findings on the original and proposed source, returns up to five new findings, and lets the model correct the file in the same turn. The check uses source passed over stdin, targets the configured Python version and ignores repository Ruff configuration. Approved pytest still checks behavior on the selected patch.

The preloaded context bundle prioritizes implementation, test and documentation landmarks ahead of secondary matches. Agent Mode calls it directly at the start. The first lookup uses the original user request so a model-generated query cannot drop task terms. Later lookups use the model's query. Follow-up tools such as symbol lookup remain deferred until needed. Agent Mode has a shared budget of eight repository calls, including discovery and search. `read_workspace_ranges` collects up to five focused windows of at most 24 lines per call. Its response shows the effective bounds, remaining call and estimated context budgets, and whether each range was returned, already shared, skipped for budget, or unavailable. Returned source is plain text so edit anchors can be copied directly. `stage_related_edits` stages up to five files in one tool call and returns per-file status and the newest review reference from the batch. Staging and both approval gates remain available after the read budget is exhausted.

The pytest profile accepts one discovered, existing relative Python file. The runner uses a shell-free subprocess, a minimal environment, bounded output, a 45-second execution limit and a Windows Job Object for descendant cleanup. The snapshot copies eligible small UTF-8 text files from disk and overlays the accepted hunks. Use **VANTA: Verification Fixture Files** in User Settings to list exact absolute paths of synthetic test files needed by the suite, including hidden or ignored fixtures. Only files in the current trusted workspace qualify. Studio lists the selected fixtures at pytest approval. These files enter the temporary snapshot without being exposed by repository discovery or read tools. Linked paths, binaries and oversized files are outside the profile. VANTA displays redacted stdout and stderr locally. TrueForge receives the result status and exit code.

An individual rejected hunk is omitted from verification and application if you approve the other hunks. Approving selected hunks seals the current revision and authorizes only those hunks. The separate pytest approval authorizes execution against that selection. **Stop** cancels the current run and revokes its pending grants.

At native review, **Reject & Revise** sends a denial for the pending review, ends the old turn, and authorizes one fresh TrueForge session using the original task. Any rejection reason you enter is optional. The follow-up carries bounded, redacted edits, each hunk’s ID and decision, nearby source captured at staging, and available syntax or staging diagnostics. The model can read current workspace source through the usual tools. Even accepted hunks remain unapplied references. **Discard & Stop** denies the whole proposal and terminates without starting a correction.

For a discovered Python handler, the initial bundle can show a locally defined decorator and one candidate it calls. These bounded source excerpts help check what setup changes before a test reaches the handler. A method name must resolve uniquely within the file to be included as a candidate.

For a documentation request, Agent Mode can link reStructuredText sections to entry points registered in the implementation. It includes existing usage and the next section boundary, including a nearby reStructuredText label when present. For command tests, it prefers an existing invocation of the registered handler when it can match the command name.

Agent Mode can also show up to two excerpts of related runtime defaults or validation from Python and JavaScript or TypeScript source. It ranks them by overlap with the request in declaration names, error text, and paths around the leading implementation. These excerpts share the context budget with implementation, test, and documentation evidence.

If approved pytest reports test failures in a target included in the patch, TrueForge may propose one correction within the current turn. VANTA closes the original proposal and shares bounded test names, affected paths, and assertion line numbers when available. It can also quote an assertion introduced by the patch from the approved source. The complete replacement requires fresh native hunk review and separate approval for the same pytest target. If correction is unavailable or fails, **Request revision** can start a user-initiated attempt with the original request and bounded diagnostics. Pytest output stays local.

Run the profile only in a trusted repository. Its Python tests run with your account privileges and can access the OS and network. The snapshot contains routine project writes within a temporary directory. VS Code controls persistence and may save dirty buffers automatically when Auto Save is enabled.
